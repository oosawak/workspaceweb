# T3Code 連携の検討資料

> 状態: 検討メモ。WorkspaceWeb と T3Code の連携はまだ実装していません。

## 目的

MindZJ の Vault にあるゲーム企画、仕様書、議事録などを T3Code の AI エージェントに渡し、調査・要約・仕様案の作成を行う。作業結果は MindZJ に戻し、内容を確認してから Vault に保存できるようにする。

MindZJ は資料とナレッジの管理、T3Code は AI エージェントの実行とコーディングを担当する想定。

## 対象範囲

依頼を作成するとき、AI エージェントに渡す範囲を次から選べるようにする。

| 範囲 | 渡すもの | 想定用途 |
| --- | --- | --- |
| 選択したノート | ノート本文と、利用者が選んだ添付資料 | 1つの仕様書の要約やレビュー |
| 選択したフォルダー | フォルダー内の資料 | 機能一式やプロジェクト資料の横断調査 |
| 選択した Vault | Vault 内の資料全体 | 全体検索、設定間の矛盾確認 |

選択範囲は依頼文に書くだけでなく、エージェントが実際にアクセスできるファイル範囲として制御する。特に「選択したノート」では、ノートと許可した添付ファイルだけを含む一時作業領域を用意する案がある。

## 想定する操作の流れ

1. MindZJ で対象ノート、フォルダー、または Vault を選ぶ。
2. 「T3Code に依頼」を選び、依頼内容と参照範囲を確認する。
3. Ubuntu 上の T3Code エージェントが選択範囲を使って作業する。
4. 作業結果を MindZJ の受け口へ返す。
5. MindZJ が結果をプレビューし、保存先を利用者に選んでもらう。
6. Vault に新しい Markdown ノートとして保存する。元ノートへの追記は別操作にする。

保存先の初期案は Vault 内の `AI/` フォルダー。ファイル名には日付と依頼タイトルを使い、同名ファイルがある場合は上書きせず確認する。

## Ubuntu 上での構成案

- MindZJ の Rust サーバーと T3Code のサーバー／エージェントを Ubuntu 上で動かす。
- MindZJ のバックエンドが依頼を作り、T3Code 側に作業範囲と指示を渡す。
- 結果は MindZJ のバックエンドに返し、バックエンドが Vault 内へ保存する。
- Vault への保存先はサーバー側で検証し、ブラウザーから任意のファイルパスを書けないようにする。

GitHub Pages は静的ホスティングのため、ローカルの T3Code や Ubuntu 上の Vault に接続する受け口にはできない。この連携は Ubuntu 上の MindZJ サーバーを使う構成が前提。

## T3Code 側で確認すること

- T3Code の公式資料では、T3Code はエージェントを動かすマシン上で動作し、CLI からフォルダーを作業場所として開けると説明されている。
- 公式資料にある Webhook は、外部サービスから T3Code のタスクを起動する用途。
- 完了した応答を任意の外部サービスへ返す共通 Webhook は、確認時点で標準機能として確認できていない。
- MindZJ から依頼を作る方法、実行中の状態を受け取る方法、最終回答を取得する方法は、実装時に T3Code の現行 API／MCP／CLI を調査して決める。
- T3Code は MIT ライセンスと記載されている。実際に同梱・改変する場合は依存物とライセンスを個別に確認する。

## セキュリティと保存方針

- Vault の読み取り範囲を依頼ごとに限定し、利用者に対象範囲を表示する。
- 結果受信口には依頼ごとの期限付きトークンを使い、外部ネットワークへ不用意に公開しない。
- 結果サイズを制限し、保存先パスはサーバー側で組み立てる。
- AI の結果は既存ノートへ自動上書きしない。MindZJ 上でプレビューしてから保存する。
- 選択した資料が AI プロバイダーへ送られることを、依頼前に利用者へ示す。
- T3Code のエージェントに Vault 全体の書き込み権限を与える案は避け、まずは範囲限定の読み取りと、MindZJ による確認後保存を検討する。

## 実装を再開するときの順序

1. Ubuntu 上で T3Code を起動し、CLI・MCP・API の外部連携方法を確認する。
2. 選択したノート1件を対象に、読み取り専用で AI に渡す最小構成を試す。
3. AI の最終結果を MindZJ に戻す方法を決める。
4. プレビューと Vault への新規 Markdown 保存を実装する。
5. フォルダー、Vault 全体へ対象範囲を広げる。
